## Recoverable bounded file reads

`Read` keeps zero-based `offset` and line-count `limit`. It now returns a bounded useful page instead of rejecting an oversized read. An optional nonnegative `cursor` resumes within the starting line, preserving the remainder of long Unicode lines. A truncated page contains the exact continuation parameters for the same file; an explicit line range remains in force. Complete small reads retain their plain-text result.

Read pages adapt to the configured context window: 16,000 characters by default, 32,000 from 100,000 context tokens, and 64,000 from 200,000, with a smaller-window guard and the existing per-round budget shared across tool calls. Continuation text fits inside the page budget. Already bounded reads are not persisted again by either the per-result or aggregate output limiter. Ordinary file protection, text/binary checks and newline behavior remain in effect.

Large tool outputs retain one immutable archive. Before presenting a path outside the project, the runtime records which task, session and workspace received it in its SQLite database. Only this recorded read grant can extend workspace-mode reading; it never grants Write/Edit access. Repeated identical delivery reuses the archive, and a reused invocation ID with different content preserves the earlier file. If saving or registration fails, the model receives a bounded warning without an unusable file promise or an instruction to repeat a potentially completed action.

A resumed task in the same session and workspace can read the issued result. File identity checks reject replaced files and filesystem links. Missing archives report that their full text is unavailable. Legacy paths can be enrolled only from the owning runtime's structured spill event, not from model/user text. Cleanup retains archives while their task or session remains in durable history; old runtime directories are protected before their first read migrates the record. An explicit durable data root is honored by isolated execution. See [the recovery design](https://github.com/Endorpheen/Igorek-Harness/blob/main/docs/architecture/TOOL_RESULT_RECOVERY.md).

### Local API tool numeric parameters

The local API server normalizes numeric tool fields using their declared input schema before type and policy checks. JSON booleans are rejected as `number` or `integer`, and fractional values are rejected for `integer`. Integral values such as `2.0` remain accepted and are passed to tools as integers. Non-finite values are rejected. The [JSON Schema numeric reference](https://json-schema.org/understanding-json-schema/reference/numeric) explains the integral-number distinction.

Legacy textual/XML calls may carry numeric parameters as text. Text is decoded only for fields explicitly declared `number` or `integer`; valid numeric values are preserved, while booleans, invalid text and non-integral integer inputs remain invalid. Required fields, additional-property checks, Edit-specific constraints and tool policy decisions continue after normalization. This update applies to the local API server's tool-input path.

!!! info "Current OpenCode policy · 0.2.12"
    While an assignment edits its original project, tool dispatch permits conversation, `Read`, `Grep`, `Glob` and the read-only `opencode_task(status)` path. Conflicting writes are blocked by a runtime guard even for forced or previously approved tool calls. An active writer prevents an overlapping assignment from starting. The model tool schema advertises only `start` and `status`; cancellation is also rejected deterministically. This does not restrict unrelated project contexts or external editors. See the [current implementation](https://github.com/Endorpheen/Igorek-Harness/blob/d0e210bbdb9db152c312dc2d089f0cf4f0b520d9/factory/core/opencode_tasks.py).

### Desktop internet search

Open **Settings → Internet search**, choose Tavily, Exa or Serper, paste a key and select **Check and save**. The check sends one search request and consumes the provider's quota. To switch back to a saved provider, leave the key field empty. Disabling search preserves saved keys. Begin a new task after changing the service.

Keys are encrypted in Desktop Vault and are not copied into model profiles, prompts or shell environments. The Vault must be unlocked; the settings-window PIN is a separate interface lock. CLI Vault storage is unchanged and is not automatically migrated into Desktop. Owner-created/imported secret values named `TAVILY_API_KEY`, `EXA_API_KEY` and `SERPER_API_KEY` can also supply credentials; `IGOREK_SEARCH_PROVIDER` records the explicit provider choice.

This route currently supports Desktop execution without KVM isolation. Tavily and Exa offer search and extraction; Serper exposes search only, so read pages with available browser tools. Provider selection is explicit: there is no silent fallback that could spend a different account's quota.

Free allowances are provider-controlled. Checked on 2026-10-21: [Exa](https://exa.ai/pricing) lists $10 monthly credits without a payment method; [Serper](https://serper.dev/) offers 2,500 initial queries without a card, not a promised recurring allowance. See [Tavily](https://www.tavily.com/pricing) for its current quota. Do not treat these allowances as unlimited or permanent.
