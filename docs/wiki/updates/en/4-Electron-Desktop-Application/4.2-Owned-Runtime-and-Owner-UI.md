## Settings inside the main window

Desktop settings and Vault now use an isolated `WebContentsView` inside the active chat window, below its shared title/menu bar. **Назад к чату** (Back to chat) closes settings and restores the existing chat without reloading it, preserving conversation state and the draft. Opening another settings section reuses the active panel. Settings file pickers are parented to the same application window.

The settings renderer retains its own preload, partition, sandbox, context isolation and exact main-frame IPC identity. Chat/browser renderers do not receive the owner API. Closing the panel destroys its privileged contents and clears private MCP setup state. Browser, ChatGPT and OpenCode surfaces are temporarily covered and laid out again on return; their attached state is retained. This change requires a Desktop update and restart, not a separate backend or model-server restart.

## Browser call feedback and post identity

Browser arguments are action-specific. `status`, `read`, `scroll`, `collect` and `result` accept only `action`; `limit` belongs to `read_post` (characters) or `comments` (up to 20 posts). Only Escape, Tab and Shift+Tab may omit `target` in a `press` call. A rejected request preserves its original error code and adds a bounded hint and typed rejection diagnostic. Invalid requests are not silently rewritten or automatically retried. On `stale_target`, read the page again and use its current `elements.ref`.

Post extraction keeps a publication's identity, body and media separate from nested quotes and linked cards. `read_post` can identify the requested publication through its own permalink even when its time element is absent or the bounded feed index omitted it. It does not substitute a quoted publication or a body link for the requested post. `post_not_found` means that the requested post could not be identified in the rendered DOM; it does not establish deletion or account access failure. Existing URL, profile, sandbox and input protections remain in force.

## Compact resource monitor and diagnostics

Enable **Монитор ресурсов → Показывать компактный монитор** in Desktop settings. The draggable panel displays CPU load, RAM usage and available NVIDIA GPU metrics: VRAM, load, temperature and power. Values refresh every two seconds while visible; disabling or closing the panel stops polling. The preference persists across launches and is off initially. Linux RAM uses available memory so reclaimable cache is not counted as application usage. Missing GPU tools or unsupported counters show unavailable values without interrupting CPU/RAM monitoring. The panel uses the local computer even when connected to a remote runtime. No model generation or server restart is performed. System Status and Task Manager keep automatic refresh and now use a compact toolbar button.

## Video thumbnails in chat

Delivered video cards, including scheduled downloads, show a preview frame before playback. A small local browser decoder samples up to three positions to avoid a black introduction; duplicate cards reuse the same thumbnail. At most two previews decode concurrently, only as cards approach the visible area. The actual player stays paused at its original position and retains its download action. A graphic fallback remains for unsupported or entirely dark clips. Previews are generated on the client through the existing authenticated, range-capable video URL; no backend transcoding service or provider request is added.

## Save images from the browser

Right-click a loaded image in the docked browser and choose **Сохранить изображение как…** (Save image as). Electron opens its save dialog and records the download in the existing download history, without navigating away from the page. The original image URL and query parameters are retained, including image links on X. The download uses the same browser session. Loaded HTTP/HTTPS images, image data URLs and web-origin blob images are supported. Existing text-copy and ChatGPT page actions remain available. This change requires an updated Desktop build and application restart.

## Notification text copying · 0.2.20

The desktop notification center preserves mouse selection across repeated snapshots and new background notifications. The unread badge continues to update. List changes wait until selection ends, while explicit Mark all read and Clear actions apply immediately. The existing native context menu copies the selected text, and Ctrl+C works normally. Notification data, ordering and diagnostics export remain unchanged.

!!! info "Responsive composer and browser dragging · 0.2.18"
    The message controls wrap according to the available panel width, including while the docked browser is resized. Long profile/model labels shrink with an ellipsis; send, stop, microphone and voice controls remain inside the form.

    `desktop_browser` now supports `drag`: select a current `elements.ref` as `target` and provide `points`, an array of 2–128 `{x, y}` coordinates normalized to 0–1 within that element. `duration_ms` is optional (100–3000, default 500). The tool presses the left mouse button, follows the path and releases it. Two opposite canvas points can draw an ellipse or rectangle with the site's selected shape tool; a longer path supports freehand drawing. Inspect the resulting screenshot before claiming that the requested drawing is complete. Stale, protected, obscured and off-screen targets are rejected. This does not enable arbitrary scripts, local-file navigation or dragging between unrelated elements.

!!! info "Composer profile selection · 0.2.16"
    Click the profile/model button beside the message field to list verified connections and start the selected worker in the **same chat**. History, working directory, draft text and pending attachments remain in place. Switching is refused while the chat or the current worker has pending work. Tool approvals from a previous profile selection are not inherited by the new selection. Locked or unverified connections remain unavailable.

!!! info "First-run model setup can be deferred · 0.2.15"
    After creating or unlocking Vault, choose **Настроить модель позже** (set up the model later) to enter the main window, or **Открыть OpenCode** to open its tab directly. No saved primary model, successful API check, running worker or first task is required. Configure OpenCode providers inside OpenCode. Deferring setup does not complete the primary-model guide, and Vault/interface-lock checks remain enforced.
