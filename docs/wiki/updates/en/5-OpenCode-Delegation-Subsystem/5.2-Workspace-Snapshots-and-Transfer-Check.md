# Direct Project Execution and Legacy Snapshot Helpers

## Current path · 0.2.12

New assignments use the selected original Git directory. `OpenCodeTasks.call(start)` performs Git admission, records `execution_mode: 'direct'` and passes the original source to the desktop controller. It does **not** call `opencode_workspace.prepare`, `inventory` or `apply_result`. A 10 GiB project does not require a second 10 GiB project copy. OpenCode's own assignment snapshots are disabled even when project configuration enables them; ordinary service data still requires space.

The runtime allows conversation and `Read`/`Grep`/`Glob` while OpenCode edits the project, and prevents conflicting main-chat writes. Internal regular file symlinks remain usable. On Windows, external or directory reparse points are rejected. There is no final conflict merge or apply operation: completion reports edits that are already present. Stopping, failure and interruption do not undo those edits.

`factory/core/opencode_workspace.py` remains in the repository for legacy compatibility and its snapshot/transfer tests. The `prepare`, `entry`, `inventory`, `changed_files` and `apply_result` implementation described below is still useful technical reference, but it must not be mistaken for the current delegation path. New native acceptance checks original-project changes before completion and the absence of task copies and OpenCode snapshots.
