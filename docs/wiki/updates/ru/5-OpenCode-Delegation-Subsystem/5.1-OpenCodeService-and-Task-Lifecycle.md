# OpenCodeService и жизненный цикл поручения

## Текущий жизненный цикл · 0.2.12

`OpenCodeService` устанавливает закреплённый официальный OpenCode 2.0.27 с проверкой SHA-512 и запускает отдельную службу с выбранным исходным проектом. `OpenCodeTasks.start()` требует `execution_mode: 'direct'`, разрешённый Git-каталог и доступный проверенный профиль модели. Запросы прежнего режима с копированием отклоняются. Нужная сессия открывается справа; начальный вызов возвращает `run_id`, не ожидая завершения работы.

Схема инструмента модели допускает только `start` и `status`. Принудительный `cancel` отклоняется с `opencode_observation_read_only` и в Python-обработчике, и в Electron, без отправки прерывания. Операция моста `answer` предназначена для точной маршрутизации ответов владельца и не является действием инструмента модели. Владелец может остановить работу в интерфейсе OpenCode.

Активный `status` обновляет сведения той же сессии через GET. Python и существующий монитор используют общий путь обработки, поэтому явное чтение не теряет и не дублирует автоматические сообщения и карточки. Без `run_id` выбирается только активное или последнее поручение исходного чата. Для завершённых записей новый живой запрос не нужен.

Дополнительный объект `progress` содержит `observed_at`, `session_active`, `latest_message`, `recent_actions`, `active_actions`, `action_counts` и признаки усечения. Python добавляет `available`, `age_seconds`, `freshness` и ограниченные сведения об ожидающих запросах владельцу. Свежесть обозначается `live`, `stale`, `historical` или `unavailable`. Публичный текст ограничен 4000 символами, списки действий — десятью элементами. Команды оболочки, исходные входы/выходы инструментов и скрытые рассуждения не пересылаются; распознанные секреты скрываются.

Долговременные записи SQLite, стабильный ключ запроса, точные ответы на формы и восстановление после перезапуска сохранены. Обнаруженная остановка владельцем закрывает устаревшие карточки и снимает запрет записи, не отвечая и не прерывая OpenCode. Завершение ставит один итоговый ход после освобождения основного чата. Изменения уже находятся в исходном проекте; переноса и автоматического отката нет.
