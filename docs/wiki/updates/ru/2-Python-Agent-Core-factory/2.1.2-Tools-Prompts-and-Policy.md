## Восстанавливаемое чтение файлов порциями

`Read` сохраняет `offset` с нумерацией строк от нуля и `limit` как число строк. Вместо отказа при большом результате теперь возвращается ограниченная полезная порция. Необязательный неотрицательный `cursor` продолжает чтение внутри начальной строки, сохраняя остаток длинных Unicode-строк. Обрезанная порция содержит точные параметры продолжения для того же файла; явно заданный диапазон строк сохраняется. Небольшие полные чтения возвращают прежний обычный текст.

Размер порции учитывает настроенное окно контекста: по умолчанию 16 000 символов, от 100 000 токенов контекста — 32 000, от 200 000 — 64 000; действуют дополнительное ограничение для маленького окна и общий бюджет раунда, разделяемый между вызовами инструментов. Подсказка продолжения входит в бюджет порции. Уже ограниченный результат чтения не сохраняется повторно ни отдельным, ни общим ограничителем вывода. Проверки обычных путей, текста/бинарных данных и поведение переводов строк сохранены.

Большой вывод инструмента сохраняется в неизменяемый архив. Прежде чем выдать путь вне проекта, рантайм записывает в свою SQLite-базу задачу, сессию и рабочую папку, которым выдан этот файл. Только такая запись расширяет чтение в режиме workspace; она не разрешает Write/Edit. Повторная выдача одинакового результата использует прежний архив, а повторный ID вызова с другим содержимым не затирает старый файл. При ошибке сохранения или регистрации модель получает ограниченное предупреждение без недоступной ссылки и без требования повторить действие, которое уже могло выполниться.

Продолжение той же сессии в той же рабочей папке может прочитать выданный результат. Проверка идентичности файла отклоняет подменённые файлы и файловые ссылки. При отсутствии архива явно сообщается, что полный текст недоступен. Старые пути регистрируются только по структурному событию сохранения в журнале владельца, а не по тексту модели или пользователя. Очистка сохраняет архивы, пока задача или сессия остаётся в истории; старые служебные папки защищены и до первой регистрации чтения. Изолированное выполнение учитывает явно заданный постоянный каталог данных. См. [описание восстановления](https://github.com/Endorpheen/Igorek-Harness/blob/main/docs/architecture/TOOL_RESULT_RECOVERY.md).

### Числовые параметры инструментов локального API

Локальный API-сервер нормализует числовые параметры по объявленной схеме до проверки типов и политики. Логические JSON-значения не принимаются как `number` или `integer`, дробные значения не принимаются как `integer`. Значения без дробной части, например `2.0`, поддерживаются и передаются инструменту как целые числа. NaN и бесконечности отклоняются. Правила целочисленных значений описаны в [справочнике JSON Schema](https://json-schema.org/understanding-json-schema/reference/numeric).

В старых текстовых/XML-вызовах числовые параметры могут приходить текстом. Такое представление преобразуется только для полей, явно объявленных как `number` или `integer`: корректные числа сохраняются, логические значения, неверный текст и значения с дробной частью для `integer` остаются недопустимыми. Затем действуют проверки обязательных и лишних полей, ограничения Edit и политика инструментов. Изменение относится к обработке входных параметров инструментов локального API-сервера.

!!! info "Текущая политика OpenCode · 0.2.12"
    Пока поручение правит исходный проект, диспетчеризация разрешает разговор, `Read`, `Grep`, `Glob` и чтение через `opencode_task(status)`. Конфликтующие изменения блокирует проверка runtime даже для принудительных и ранее одобренных вызовов. Работающий писатель не даёт начать пересекающееся поручение. Схема инструмента модели содержит только `start` и `status`; отмена дополнительно отклоняется детерминированно. Ограничение не распространяется на несвязанные проекты или внешние редакторы. См. [текущую реализацию](https://github.com/Endorpheen/Igorek-Harness/blob/d0e210bbdb9db152c312dc2d089f0cf4f0b520d9/factory/core/opencode_tasks.py).

### Интернет-поиск в Desktop

Откройте **Настройки → Интернет-поиск**, выберите Tavily, Exa или Serper, вставьте ключ и нажмите **Проверить и сохранить**. Проверка выполняет один поисковый запрос и расходует лимит службы. Для возврата к сохранённой службе оставьте поле ключа пустым. Выключение поиска сохраняет ключи. После смены службы начните новую задачу.

Ключи зашифрованы в Desktop-хранилище и не копируются в профили моделей, промпты или окружение команд. Хранилище должно быть открыто; PIN окна настроек блокирует интерфейс отдельно. CLI-хранилище не меняется и автоматически в Desktop не переносится. Секреты `TAVILY_API_KEY`, `EXA_API_KEY` и `SERPER_API_KEY`, созданные или импортированные владельцем, тоже могут использоваться; `IGOREK_SEARCH_PROVIDER` сохраняет явно выбранную службу.

Сейчас этот путь работает в Desktop без KVM-изоляции. Tavily и Exa предоставляют поиск и извлечение текста; Serper — только поиск, страницы можно читать доступными инструментами браузера. Служба выбирается явно: автоматического переключения с расходованием лимита другого аккаунта нет.

Бесплатные лимиты определяет провайдер. На 21.10.2026 [Exa](https://exa.ai/pricing) указывает $10 кредитов ежемесячно без платёжного средства, [Serper](https://serper.dev/) — 2500 стартовых запросов без карты, без обещания ежемесячного возобновления. Актуальный лимит Tavily указан на [странице тарифов](https://www.tavily.com/pricing). Эти условия не означают безлимитный или бессрочный бесплатный доступ.

### Подробные причины отказов браузера (ещё не выпущено)

При отказе перечисляются недостающие и недопустимые поля схемы и разрешённые поля. Значения параметров и произвольные неизвестные имена полей в диагностику не копируются. Таймаут ответа Desktop указывает этап ожидания и длительность, сохраняя неопределённость результата. Android сохраняет переданную причину и краткую подсказку в объяснении ошибки.

### Соответствие вызовов и результатов (ещё не выпущено)

Локальный адаптер истории Anthropic сопоставляет последний результат инструмента с предшествующим вызовом по ID. Параллельный результат не получает чужое имя или аргументы; более поздний ожидающий вызов не заменяет завершённую пару. Результат без найденного вызова сохраняет свой текст без выдуманной привязки. Для старых результатов без ID сохранено поведение ближайшего предшествующего вызова. Пустые результаты сохраняют ID и явный признак ошибки: вместо пустой ошибки больше не подставляются старый вывод или сообщение об успехе. Структурированные thinking-блоки остаются отдельно от видимого текста; обычный текст не классифицируется по формулировкам.

### Определение рабочей папки API (ещё не выпущено)

Файловая политика API сохраняет полную строку рабочей папки сессии, включая пробелы. Существующие папки, например `release.v2`, остаются папками при определении относительных путей к файлам. Исправления сохраняют действующие ограничения корней, явно разрешённые дополнительные корни и защиту управляющих файлов; новых разрешений на чтение или запись они не предоставляют.

### Создание навыков и откат при сбое проверки (ещё не выпущено)

`skill_manage` создаёт пакет только после исключительного создания новой папки; занятый путь отклоняется без присвоения или удаления его содержимого. Если первая запись не удалась, очищается только эта новая папка пакета, чтобы создание можно было повторить. Исключение проверяющего модуля считается отказом изменения и запускает существующий откат правки, замены текста, записи или удаления вспомогательного файла. Статические запреты и запрет правок во внешних каталогах сохраняются. Восстановление требует исправной записи в файловую систему; неисправимые ошибки хранилища по-прежнему возвращаются как ошибки.

### Совместимость текстового парсера API (ещё не выпущено)

Блоки кода в тройных обратных кавычках распознаются с переносами строк LF и Windows CRLF. Пустая Bash-команда не содержит пути к файлу и больше не вызывает ошибку индекса при его извлечении. Действующие фильтры имён файлов, защита файлов инструкций и ограничения сводок Read сохранены. Разбор текста не выполняет содержащийся в нём код или команду.
