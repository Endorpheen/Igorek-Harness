## Purpose and Scope

This page documents the architecture and implementation of the Windows native pipe adapter and process hooking subsystem (`igorek-pipes.dll`). This component provides restricted Windows x64 process pipe redirection and process manipulation capabilities by leveraging vendored Microsoft Detours (`v4.0.1`) and custom DLL injection entrypoints (`IgorekEmbed`).

Sources: `desktop/packaging/build-windows-pipes.py:1-15`, `desktop/native/windows-pipes.def:1-4`

---

## 1. Vendored Microsoft Detours & Source Pinning

The harness vendors Microsoft Detours version 4.0.1 under `desktop/native/vendor/detours/` to hook and redirect native Win32 API calls in sandboxed Windows environments. 

The integrity of the vendored Detours files is strictly verified by the build script using cryptographic SHA-256 hashes defined in `SOURCE.json`. The tracked source files include core hooking (`detours.cpp`, `detours.h`), process creation helpers (`creatwth.cpp`), disassemblers (`disasm.cpp`, `disolx64.cpp`, `disolx86.cpp`, etc.), and image management utilities (`image.cpp`, `modules.cpp`, `uimports.cpp`).

Sources: `desktop/native/vendor/detours/SOURCE.json:1-23`, `desktop/packaging/build-windows-pipes.py:18-22`, `desktop/native/vendor/detours/LICENSE.md:1-24`

## 2. Build Pipeline & Compilation (`build-windows-pipes.py`)

The pipe adapter DLL (`igorek-pipes.dll`) is compiled exclusively on Windows hosts (`os.name == 'nt'`) via `desktop/packaging/build-windows-pipes.py`. The build automation performs the following verification and compilation sequence:

1. **Host & Checksum Verification**: Validates that the execution host is Windows and computes SHA-256 digests for all files listed in `SOURCE.json` [desktop/packaging/build-windows-pipes.py:13-22]().
2. **Compiler Discovery**: Locates the latest Visual Studio installation path using `vswhere.exe` and retrieves the x64 build environment setup script `vcvars64.bat` [desktop/packaging/build-windows-pipes.py:23-29]().
3. **Compilation**: Invokes the Microsoft C/C++ Optimizing Compiler (`cl.exe`) with static multithreading (`/MT`), optimization level `/O2`, C++17 standard conformance (`/std:c++17`), and targeted Windows 10/11 APIs (`/D_WIN32_WINNT=0x0A00`) [desktop/packaging/build-windows-pipes.py:36-40]().
4. **Linkage**: Links against `advapi32.lib` and `user32.lib` using the definition file `windows-pipes.def`, applying ASLR (`/DYNAMICBASE`) and DEP (`/NXCOMPAT`) mitigations [desktop/packaging/build-windows-pipes.py:39-40]().

## 3. DLL Injection & `IgorekEmbed` Entrypoint

The exported entrypoint of the pipe adapter is `IgorekEmbed`, declared in the module definition file `desktop/native/windows-pipes.def`. This entrypoint facilitates DLL injection into target sandboxed processes on Windows.

```
LIBRARY igorek-pipes
EXPORTS
    IgorekEmbed @1
```

Sources: `desktop/native/windows-pipes.def:1-4`

The injection and hooking machinery relies on Detours process creation wrappers (`creatwth.cpp`) which inspect PE headers via `LoadNtHeaderFromProcess` and `EnumerateModulesInProcess`, and allocate trampoline and redirection memory near the base address (`FindAndAllocateNearBase`) [desktop/native/vendor/detours/creatwth.cpp:53-200](). Core detour routing mechanisms in `detours.cpp` handle instruction disassembly, jump generation (`detour_gen_jmp_immediate`, `detour_gen_jmp_indirect`), and import table traversal to safely intercept pipe and process creation APIs [desktop/native/vendor/detours/detours.cpp:130-198]().
