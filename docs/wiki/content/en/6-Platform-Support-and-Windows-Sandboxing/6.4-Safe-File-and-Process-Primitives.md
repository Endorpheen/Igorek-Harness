## Purpose & Scope
This section details the low-level safety primitives implemented in the Igorek-Harness codebase to ensure thread-safe, process-safe, and workspace-bounded disk and process operations. This covers atomic file writes, workspace-bounded file resolution, cross-process exclusive locks, secure parent-pinned path resolution, DACL preservation under Windows, and bounded checkpointed `git` execution with isolation guarantees.

Sources: `tests/test_platform_support.py:1-30()`, `factory/core/checkpoint_manager.py:1-55()`, `factory/core/readonly_git.py:1-48()`

## 1. Atomic Writes and Workspace-Bounded Reads
File manipulation within agent workspaces must protect against partial writes, symlink traversal attacks, and uncontrolled resource consumption. The codebase implements atomic write cycles and safe file handles via `factory/core/artifact_files.py` (referenced by test suites).

* `atomic_write_file`: Writes data to a temporary file within the target directory before performing an atomic rename operation, preventing torn reads or half-written states if an agent task or runtime crashes mid-write.
* `open_regular_file`: Opens regular file paths while enforcing strict checks against irregular file types, pipes, or unresolvable symlinks.
* `open_workspace_artifact`: Resolves paths relative to an authorized workspace root, throwing errors if traversal sequences (`..`) attempt to escape the workspace boundary.

## 2. Exclusive Locks
To coordinate concurrent access to shared agent state, databases, or workspace state files across multiple threads and worker processes, the codebase provides cross-platform exclusive locking primitives.

* `exclusive_lock`: Implemented under `factory/core/platform_support` [tests/test_platform_support.py:28](), this primitive acquires an exclusive advisory or mandatory file lock depending on the host operating system, preventing race conditions during concurrent state modifications by background workers or API request threads.

## 3. Pinned Parents and DACL Preservation (Windows Security)
On Windows platforms, agent execution and OpenCode delegations require robust hardening against unauthorized token manipulation, clipboard access, and insecure file DACLs (Discretionary Access Control Lists). 

* `protect_directory`: Used in Windows-owned test fixtures [tests/test_platform_support.py:35-38]() to lock down sensitive directories.
* DACL Checks: Validation routines inspect parent directories (`private_parent`, `outside`) to ensure that arbitrary unprivileged processes cannot modify directory ACLs or access restricted canary files (`canary.txt`, `low-canary.txt`) [tests/test_platform_support.py:53-139]().
* Restricted Process Tokens: Restricts processes using job objects and restricted tokens to strip unnecessary capability SIDs and prevent process tampering [tests/test_platform_support.py:53-59]().

## 4. Checkpointed Git Execution & Read-Only Isolation
Agent sessions utilize Git for checkpointing workspace states and managing diffs. To prevent malicious repositories or untrusted `.git` configurations from executing arbitrary code on the host, Git operations are isolated through `factory/core/checkpoint_manager.py` and `factory/core/readonly_git.py`.

### Key Functions and Modules
* `_git_to_files`: Manages subprocess execution on Windows by writing streams to temporary files rather than piping, preventing deadlocks and handle leaks when a timed-out Git process is terminated [factory/core/checkpoint_manager.py:30-44]().
* `_git_command`: Wraps `_git_to_files` (on Windows) or `subprocess.run` (on POSIX) while applying unprivileged argument filters (`_checkpoint_argv`) when running inside sandbox guests [factory/core/checkpoint_manager.py:46-54]().
* `_checkpoint_text`: Inspects private shadow blobs, verifying object IDs against strict SHA-1/SHA-256 patterns (`_FULL_REVISION_RE`) and enforcing size boundaries (`MAX_CHECKPOINT_PREVIEW_BYTES`) before parsing diff text [factory/core/checkpoint_manager.py:56-78]().
* `read_git`: Enforces read-only Git operations via Bubblewrap (`bwrap`) namespaces (`--unshare-net`), restricted environment maps (`git_environment`), and frozen configuration parsing (`_frozen_config`, `SAFE_KEYS`) to block malicious repository configuration exploits [factory/core/readonly_git.py:30-158]().
