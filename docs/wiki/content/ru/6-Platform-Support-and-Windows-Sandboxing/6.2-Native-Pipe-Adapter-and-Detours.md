## Назначение и область охвата

Эта страница описывает архитектуру и реализацию нативного пайп-адаптера Windows и подсистемы перехвата процессов (`igorek-pipes.dll`). Этот компонент обеспечивает перенаправление пайпов и возможности манипуляции процессами в ограниченных средах Windows x64, опираясь на вендоренную копию Microsoft Detours (`v4.0.1`) и собственные точки входа для DLL-инъекции (`IgorekEmbed`).

Источники: `desktop/packaging/build-windows-pipes.py:1-15`, `desktop/native/windows-pipes.def:1-4`

## 1. Вендоренная копия Microsoft Detours и фиксация исходников

Харнесс держит вендоренную копию Microsoft Detours версии 4.0.1 в `desktop/native/vendor/detours/`, чтобы перехватывать и перенаправлять нативные вызовы Win32 API в средах Windows под песочницей.

Целостность вендоренных файлов Detours жёстко проверяется скриптом сборки по криптографическим хешам SHA-256, заданным в `SOURCE.json`. Отслеживаемые исходники включают ядро перехвата (`detours.cpp`, `detours.h`), хелперы создания процессов (`creatwth.cpp`), дизассемблеры (`disasm.cpp`, `disolx64.cpp`, `disolx86.cpp` и др.) и утилиты управления образами (`image.cpp`, `modules.cpp`, `uimports.cpp`).

Источники: `desktop/native/vendor/detours/SOURCE.json:1-23`, `desktop/packaging/build-windows-pipes.py:18-22`, `desktop/native/vendor/detours/LICENSE.md:1-24`

## 2. Конвейер сборки и компиляция (`build-windows-pipes.py`)

DLL пайп-адаптера (`igorek-pipes.dll`) компилируется только на хостах Windows (`os.name == 'nt'`) через `desktop/packaging/build-windows-pipes.py`. Автоматизация сборки выполняет следующую последовательность проверок и компиляции:

1. **Проверка хоста и контрольных сумм**: убеждается, что хост выполнения — Windows, и вычисляет дайджесты SHA-256 для всех файлов, перечисленных в `SOURCE.json` [desktop/packaging/build-windows-pipes.py:13-22]().
2. **Поиск компилятора**: находит путь к последней установленной Visual Studio через `vswhere.exe` и достаёт скрипт настройки x64-окружения сборки `vcvars64.bat` [desktop/packaging/build-windows-pipes.py:23-29]().
3. **Компиляция**: вызывает оптимизирующий компилятор Microsoft C/C++ (`cl.exe`) со статической многопоточностью (`/MT`), уровнем оптимизации `/O2`, соответствием стандарту C++17 (`/std:c++17`) и нацеливанием на API Windows 10/11 (`/D_WIN32_WINNT=0x0A00`) [desktop/packaging/build-windows-pipes.py:36-40]().
4. **Линковка**: линкует с `advapi32.lib` и `user32.lib` через файл определений `windows-pipes.def`, применяя митигации ASLR (`/DYNAMICBASE`) и DEP (`/NXCOMPAT`) [desktop/packaging/build-windows-pipes.py:39-40]().

## 3. DLL-инъекция и точка входа `IgorekEmbed`

Экспортируемая точка входа пайп-адаптера — `IgorekEmbed`, объявленная в файле определений модуля `desktop/native/windows-pipes.def`. Эта точка входа обеспечивает DLL-инъекцию в целевые процессы под песочницей на Windows.

```
LIBRARY igorek-pipes
EXPORTS
    IgorekEmbed @1
```

Источники: `desktop/native/windows-pipes.def:1-4`

Механика инъекции и перехвата опирается на обёртки создания процессов Detours (`creatwth.cpp`), которые инспектируют PE-заголовки через `LoadNtHeaderFromProcess` и `EnumerateModulesInProcess` и выделяют память под трамплины и перенаправление рядом с базовым адресом (`FindAndAllocateNearBase`) [desktop/native/vendor/detours/creatwth.cpp:53-200](). Основные механизмы маршрутизации detour в `detours.cpp` отвечают за дизассемблирование инструкций, генерацию переходов (`detour_gen_jmp_immediate`, `detour_gen_jmp_indirect`) и обход таблицы импорта, чтобы безопасно перехватывать API создания пайпов и процессов [desktop/native/vendor/detours/detours.cpp:130-198]().
